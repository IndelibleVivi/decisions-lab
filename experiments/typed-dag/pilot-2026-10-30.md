# E3 首轮模型实验：字段正确以后，还缺什么？

**状态：126 次原生请求已完成，112/112 个终局样本均有结果。** 以下事前设计在调用前冻结，实测结果单独列于文末。研究对象是已有的 7 个原创开发用例／6 个 source families，不是新建的 held-out 测试集。原始响应、运行 manifest、凭据和账户观察只保存在本机；本页只公开设计与汇总。

## 问题与可拒绝的解释

本轮检验：将原文压缩为类型化字段，再做 Decimal 计算与原生 decision 时，终局错误来自抽取、计算、证据选择，还是 schema 没有承载决定所需的事实？

三个竞争解释分别接受检查：如果 gold extraction 消除错误，抽取是一个可定位的限制；如果字段完全正确仍不能区分要求相反动作的两篇原文，则不能把错误继续归给提取器；如果补入目标现行状态的 gold evidence 改变结果，说明该证据在这份有限题本上有决策价值。干预可能相互作用，效果不能相加为独立的因果贡献。

## 固定设计

- 抽取：Cloudflare 原生 `@cf/cloudflare/clairic`；判断：OpenAI 官方 `POST /v1/decisions`、`gpt-6-luna`。不混入旧 OpenRouter Luna 结果。
- 题本：`typed_dag.build_suite(seed=20261030)`，保留现有 7 cases、动作、损失矩阵、缺失值和现行版本约定。每个 case 两次重复；重复与表示共用来源，不当作独立样本。
- 抽取的 14 个请求只采一次；所有需要原生抽取的条件应用同一份 retained collection。下游始终使用对应 replicate 的实际字段，gold intervention 除外。
- 每个条件有 14 个 planned 终局样本，共 112 个；最多 14 次抽取加 112 次判断，即 **126 次原生请求**。错误和 uncertain send 计入上限，不自动重试、不以新请求替换失败。

| 条件 ID | 可见输入与干预 | 原生抽取 |
| --- | --- | --- |
| direct | 完整原文直接判断 | 无 |
| fields | 实际字段与 Decimal 结果 | 共享 |
| source | 实际字段、Decimal 与实际提取且核验通过的 quote | 共享 |
| fields-gold-extraction | gold fields 与相同 Decimal 过程 | 无；明确标记 gold-derived |
| source-gold-extraction | gold fields、相同 Decimal 与证据选择过程 | 无；明确标记 gold-derived |
| fields-gold-calculation | 实际字段，计算部分替换为 gold 操作数与结果 | 共享 |
| source-gold-calculation | 实际字段及证据，计算部分替换为 gold | 共享 |
| source-gold-retrieval | 实际字段与计算，证据替换为目标现行状态原文 | 共享 |

先采 direct 条件，其首个请求同时承担原生契约检查，仍留在正式分母。其余条件使用固定 seed 排序，各 collection 内请求由同一预先指定 seed 随机排列。不同条件按 block 顺序执行，时间／服务变化仍可能形成混杂，不能据此作一般因果推断。

gold 只由本地 evaluator 与干预路径持有；provider body 不包含正确动作、loss、oracle、评分或 gold 标签。gold 值是干预后确实可见的输入，不能将这种条件称作完全由模型完成的工作流。

## 终点与比较

主比较是 `fields → source`，同时保留 `direct → fields` 和 `direct → source`。每项 gold 干预只与对应未干预条件比较，另外比较 `source-gold-extraction → source-gold-retrieval` 时明确两侧替换的是不同阶段，不能解释为单一因素效应。

报告每个 case／replicate 的终局动作、完整 planned 分母、正确数、业务补材料、API unknown／refusal／error／missing 和终局 loss；分别检查字段差异、Decimal 算术一致性、证据支持关系和 projection 下的合理动作。终局 loss 使用题本既有矩阵，完成的 API failure 代价为 12；尚未完成的样本保持 missing，完整总损失与配对差值保持 null。

逐 family 保留结果；总体另给先在同 case 内平均 repeats、再在同 family 内平均 cases、最后对 6 个 families 等权的描述性平均损失。全部条件都完成时才给完整平均；不对 14 次重复构造独立样本置信区间。计量按实际 request 归属一次，共享抽取不在条件间重复相加。

## 预算、停止与恢复

运行须另行记录操作者对模型、此题本与整轮上限的明确授权。整个实验使用一个累计计量器，最多 126 attempts、2 MB 序列化输入和 1 USD 的本地保守费用预留；单阶段 collector 限额不代替整轮限制。预留参考每次请求的模型窗口／原生字段数与最新公开费率，在请求发送前记账；收到有效 usage 后按费率加余量回填。它是停止控制，不是 provider 账单凭证；缺失计量保留整次预留并停止。

2026-10-30 核对的公开基价：官方 Decisions 未缓存输入 0.10 USD／百万 tokens、输出不收费；缓存写入、区域与长上下文另有规则。Clairic 为 0.10 USD／百万输入 tokens，Workers AI 按 Neurons 结算。执行时不设置缓存、区域或额外图像选项；费用预留仍包含余量。[OpenAI Decisions](https://developers.openai.com/api/docs/guides/decisions)、[Clairic 模型说明](https://developers.cloudflare.com/workers-ai/models/clairic/)、[Workers AI 定价](https://developers.cloudflare.com/workers-ai/platform/pricing/)。

HTTP 错误、原生解析错误、usage 缺失或异常、凭据问题、网络中断、费用或调用限额触达即停。已发请求与 raw bytes 留存，uncertain 不重发，未发样本保留 planned missing。继续运行先确认原进程结束、原始证据与 source 未变；原 collector 的 checkpoint 只用于跳过已发请求，不能提高预算或覆盖失败。模型或题本变化需要新设计，不静默修改本轮。

本轮只发送仓库已有的原创合成输入，不使用私人资料、不执行模型建议、不充值、不更改账户配置。结果可由原生 records、typed DAG apply/report/compare 重新计算；跨阶段执行的本机 operator 和原始运行目录不进入站点。

## 本轮不能回答的事

这是机制诊断 pilot。普通模型摘要的等 token 对照尚未实现，本轮因此不主张类型化表示优于一般摘要；实际 token 与延迟只作描述。公开真实材料、未见机制、多语言校准、人类验证成本和生产收益各需要独立研究。研究台界面已经具备，界面验收不替代这些研究证据。

## 2026-10-30 实测结果

实际完成 14 次 Clairic 抽取、112 次官方 Luna 判断，全部 HTTP 200，没有重试、API unknown／refusal／error 或 planned missing。累计序列化输入 223,910 bytes；原生 usage 汇总为 Clairic 14,770、Decisions 56,006 input tokens。usage、公开费率估计与账户账单分别保留，不将估计称为已结算费用。采集已结束，本轮授权不延伸为后续自动调用。

| --- | ---: | ---: | ---: | ---: |
| direct | 14/14 | 2 | 0 | 0 |
| fields | 10/14 | 6 | 8 | 0.333333 |

表中两次本来就应补材料的样本来自缺少运费的用例，不是 API failure。其余错误均为过度补材料，没有错误建议继续或错误核对争议。paired delta 的方向为右侧减左侧：`fields → source` 为 0，`source → source-gold-retrieval` 为 −8，`fields → fields-gold-calculation` 为 +4，分母均为 14 个完整 pairs。

### schema 缺口没有被正确抽取解决

schema-gap 两个用例的原文要求相反动作，gold fields 完全相同。Clairic 在这 4 个 replicate 样本上全部严格抽取正确，但 fields 与 source 均选择补材料。gold extraction 仍为同样结果；gold retrieval 增加目标现行状态后，4 个样本全部恢复正确。这里支持的是特定 schema 丢失了决定性事实，不能推导出一般检索系统已解决来源问题。

### 普通来源版没有真正获得可采用的 quote

本轮完整字段严格匹配为 78/88；10 个差异中，8 个是状态摘录省略了要求的「目标现行状态：」前缀和结尾标点，另 2 个是缺运费时模型仍给出数值 `computed_total`。42/42 个实际计算操作数（含显式 null）均匹配；Decimal 没有采用缺运费时的模型总额，正确保留计算不完整。

4 个带状态字段的用例各两次都返回了原文中的短摘录，但当前来源校验还要求完整的目标现行状态前缀，因此 8 个 candidate 均未成为有效引用；其余 6 个样本的 schema 本就不含状态字段。**普通 source 条件的 14 个样本都没有有效 quote。** 它仍保留字段中的短摘录，Luna 可据此判断部分样本，所以不能把 `fields → source` 的零差值解释为“有效来源链接没有价值”。下一设计需要区分摘录内容、实体／版本绑定和可核验 locator，保持歧义与旧版本保护，不应为了通过校验而直接信任任意 substring。

冻结 evaluator 的 `honest_under_projection` 实际表示与一个严格要求前缀的确定性 body policy 是否一致。本轮普通 fields/source 为 6/14；这不是模型诚实度，也不是语义充分性的独立真值。原生回答、原始报告与这一测量限制一起保留，不能事后改变 evaluator 来提高分数。

### gold calculation 带来的变化不能归因为算术

`current-version-correction` 的两个重复在 fields 中都答对，在 fields-gold-calculation 中都改成补材料。逐项核对两侧 body 后，变化仅是等值 Decimal 的序列化：例如 `300` → `300.00`、`50` → `50.00`、`950` → `950.00`。原先的算术已经正确，这个条件没有纠正数值错误。

因此额外的 loss 4 是值得后续检查的表示／执行条件敏感性信号，**不是“正确计算使推理变差”的因果证据**。后续须固定相同数值表示、交错请求顺序并增加独立重复，才能区分格式、时间或服务变化。没有为追逐这次差异追加调用，也没有将原始结果替换为重跑结果。
