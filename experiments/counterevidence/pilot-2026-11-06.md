## 研究问题与固定设计

当初步结论可能来自过期、错实体、漏掉例外或效力不明的材料时，按需核查能否降低错误承诺？它能否在已有充分材料或来源不可得时及时停止？全部读取的额外材料成本是否带来终局收益？

题本由 `counterevidence.build_design(seed=20261106)` 生成：六类原创合成机制，每类两个有限世界、每世界两次重复，每个条件 24 个 planned episodes。三条件使用相同世界、初始材料、损失矩阵和原生模型；模型不接收完整 hypotheses、精确 posterior 或本地 oracle。

| 条件 | 读取方式 | 原生请求上限 |
| --- | --- | ---: |
| immediate | `no-query`，初始材料后立即决定或暂缓 | 24 |
| adaptive | 逐轮核查，最多三次本地读取，然后终止 | 96 |
| full | `read-all`，全部观察先读取并收费，一次终局判断 | 24 |

固定官方 `POST /v1/decisions` 与 `gpt-6-luna`，每请求一题，不使用 Responses、Chat 或第三方路由。请求顺序按固定 seed 打乱，条件按轮交错；依赖回合等待实际前轮回答。首请求即为正式样本，计入计划与预算，不额外复制成预检。

主要终点为 family 等权的查询成本加终局损失；同时报告错误承诺、暂缓、已读来源、完整 planned 分母、API failure/missing、原生调用、input tokens 与请求耗时。读取成本 1、错误承诺 10、暂缓 3、API failure 12。实际单轨迹损失不冒充完整模型策略的 expected regret；材料成本、API 用量和账单不合并。

立即停止、固定检查表、myopic 与多步最优作为 synthetic 控制。有限 oracle 知道完整观察模型，原生模型只看可见材料；oracle 是带额外信息的参照，不是同信息公平比较。六个机制和重复不足以提供总体泛化区间。

## 调用范围与停止

全程上限为 **160 attempts、4 MB 序列化输入、US$1 本机保守费用预留**；正式设计最多 144 次请求。仅使用现有官方专属凭据与 credits，不充值、改账户设置、切换模型或自动重试。HTTP/原生契约错误、usage 缺失或异常、网络/凭据异常即停止；uncertain 保留，不重新发送，未发送样本保持 missing。

2026-11-06 核对：Decisions 未缓存输入 0.10 USD／百万 tokens、输出不收费；缓存、区域及长 context 规则另算。每次请求前保守预留，收到有效 usage 后回填。费用估计不是账户账单或余额。[官方 Decisions 定价](https://developers.openai.com/api/docs/guides/decisions)。

只发送原创合成材料及其可见回合。查询只揭示本地证据，不访问外部网站或执行建议。原始 bytes、冻结 source、operator 和账户计量在 Git 外保留，公开正文只记录合成设计、方法与汇总。

## 结果解释

此设计检验有限材料环境中的来源核查与停止，不证明开放检索、现实法律判断、模型内部信念修正或任意概率错设恢复。三条件使用不同数量的模型请求和输入 tokens，不能声称等 API 成本优势。已见题作开发证据，后续迁移需要新的资料与机制。
