原采集目录和已关闭的 dispatch 保留。新续采记录绑定原协议、源码、题本、原始 collection 和计量；合计预算包含全部既有 attempts，仍为 **160 attempts、4 MB 序列化输入、US$1 本机保守费用预留**。保留旧失败请求的完整费用预留。遇到新的 HTTP／原生契约错误、usage 异常或网络异常仍立即停止，无自动重试、fallback 或模型切换。无新凭据、充值或账户设置变更。

## 验证与解释

真实调用前，用无网络的恢复模拟检查：旧 16 次接收原样保留；仅未发送请求进入 transport；失败仍进入完整 planned 分母；全部结束后重复恢复不再发送请求。续采结束后核对 raw bytes、原生状态、usage、逐回合请求及重新评分，并把三条件轨迹导入本机 Studio。运行原始资料仍不进入 Git 或站点。

主要终点及限制沿用原协议。另须承认这是一份**跨日期续采**：immediate 的前 16 次来自前轮，其余请求在后轮采集。模型使用服务 alias，日期与请求顺序可能形成混杂；不能把三条件差异解释为受控的同一时点因果效果。保留 API failure 的总损失和成功回答中的业务行为分别解释，不用删掉失败的子集替代主要终点。

### 来源轨迹与停止

下表每格为“读取次数 / 业务暂缓数 / 总损失”，每个机制每条件 4 episodes。

| 机制 | immediate | adaptive | full |
| --- | --- | --- | --- |
| stale-version | 0 / 4 / 12 | 6 / 0 / 6 | 8 / 0 / 8 |
| wrong-entity | 0 / 4 / 12 | 6 / 0 / 6 | 8 / 0 / 8 |
| omitted-exception | 0 / 3 / 21¹ | 4 / 2 / 10 | 4 / 2 / 10 |
| unsupported-authority | 0 / 4 / 12 | 8 / 0 / 8 | 8 / 0 / 8 |
| unavailable-source | 0 / 4 / 12 | 8 / 4 / 20 | 8 / 4 / 20 |
| already-sufficient | 0 / 0 / 0 | 4 / 0 / 4 | 4 / 0 / 4 |

¹ 另有 1 个原轮 API failure，损失 12；不计为业务暂缓。

- **已有充分材料仍重复核查。** `already-sufficient` 初始已附完整现行来源，immediate 的 4 个样本全部正确决定；adaptive 的 4 个样本仍各读一次确认材料。此处观察到的是停止不足。
- **不可得来源得到保留不确定的终局，但多读了一份档案。** adaptive 在 4 个样本中均先查当前来源、再查旧档案，最后暂缓。模型事先不知道当前来源不可得，不能把第一次查询直接判为浪费；有限 oracle 的信息优势仍需保留。
- **看到足够的例外条款也未必承诺。** `omitted-exception/b` 的两次重复在读到“观察期已经结束，可以启用。”后仍选择暂缓；full 也相同。本地规则判定该来源足以支持 `commit:allow`。原生输出只提供动作，不能推断模型为什么暂缓或其内在信念。

本轮支持的观察是：核查条件将更多样本推进到正确承诺，但 adaptive 没有普遍学会节制核查，也未优于 full 的终局动作。首轮 synthetic 最优控制均值 1.166667 是掌握完整有限环境的参照，不是同信息模型基线。下一项值得检验的是来源已经足够时的停止，以及同信息、可比调用预算下的核查收益；本轮没有开展新的调参或追分重跑。

**11-07 方法澄清：** 本轮连已附充分原文的输入也包含统一的 `provisional`／待核实警告。“停止不足”在此只描述有限题本中的重复读取，不能据此归因模型内在能力；“没有学会”也不表示进行过训练。三个条件均无错误承诺，观察到的主要差别是暂缓与正确承诺的覆盖。后续[材料 × 提示实验](../inquiry-framing/README.md)将这两个因素分开控制；本轮数据和评分不改写。
