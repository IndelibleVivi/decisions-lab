# Schema 反例到主动核查：首轮 Luna 实验

**状态：2026-10-30 实采完成；48 次原生请求、32/32 episodes 到达终局，无 API failure 或 missing。** 本页事前设计在调用前冻结。原始响应、源码快照、operator、凭据与账户计量只保存在本机，公开页面只保留合成研究协议与汇总。

## 固定问题与设计

本轮检验：当相同字段不能支持共同最优行动时，模型是否选择有价值的来源核查；在证据不可得或已有稳健答案时，是否停止？完整原文是否降低终局错误，是否值得额外读取成本？

题本由 `schema_inquiry.build_design(seed=20261030)` 生成，固定 `entity`、`status` 两个字段。4 类机制、8 个显式有限世界，每个重复两次；共 16 episodes／条件。字段来自合成 oracle，抽取错误不是本轮处理变量。完整假设表、精确先验、查询映射与损失矩阵是两条件共同可见契约；实际 world 隐藏。

| 条件 | 读取方式 | 模型责任 | 请求上限 |
| --- | --- | --- | ---: |
| adaptive | 起初只给字段，逐轮揭示所选来源 | 查询或停止，再作终局决定 | 48 |
| full | 先读取两份材料、提供可得完整原文 | 一次终局决定 | 16 |

原生路线固定 OpenAI 官方 `POST /v1/decisions`、`gpt-6-luna`，使用现有专用凭据。每个原生请求一题，不使用 Responses、Chat 或第三方路由。以固定 seed 随机化每轮请求顺序；条件按轮交错收集，依赖后续轮仍必须等待实际前轮响应。首请求也计入正式分母，不做额外计费预检。

本地查询成本与终局损失沿[实验契约](README.md)：每次读取 1、错误终局 10、暂缓 3、API failure／missing 12。full 在首次模型调用前记入两次读取，不把本地读取伪造为 provider 调用。主要终点是 family 等权的总损失，同时保留终局损失、查询成本、动作、暂缓、API failures、missing、原生请求数、usage 和延迟。原生账单估计与合成效用不合并。

离线竞争解释包括立即停止、固定检查表、一步 VOI 和多步 oracle。默认题本上前两者总损失分别 18、22，后两者均 10（8 worlds）；这些是代码控制，不能当作模型成绩。每类仅一个作者设计机制，重复不增加来源独立性；不报告总体泛化置信区间。

## 调用边界与停止

本轮最多 **64 attempts、1 MB 序列化输入、US$1 本地保守费用预留**，已有 credits，不充值、不换模型、不开付费 fallback、不自动重试。HTTP 错误、原生契约错误、usage 缺失或异常、凭据或网络异常均停止；uncertain 保留且不重发，未发送样本仍为 planned missing。成功应用的每个原生回合保留原始 bytes，后续 body 由其实际答案产生。

2026-10-30 核对：Decisions 未缓存输入为 0.10 USD／百万 tokens、输出不收费；cache writes、长上下文与区域溢价另有规则。本机在请求前按完整模型窗口及费率余量预留，收到有效 usage 后回填；未知值不填零，费用估计不称为账户账单。[Decisions 定价说明](https://developers.openai.com/api/docs/guides/decisions)、[Luna 模型窗口与费率](https://developers.openai.com/api/docs/models/gpt-6-luna)。

只发送仓库原创合成题本与它派生的可见回合；不发送私人资料、不调用外部查询工具、不执行动作建议。此轮不续跑旧 E3 或旧 E2 采集。协议改变后须形成新设计，不能为追求成绩重跑覆盖。

## 解释边界

更低的合成总损失只说明该成本矩阵下的规划结果。完整原文、多轮调用的 token 与时间不同，本轮不主张等 token 优越性。精确字段、已知有限假设与可验证的本地来源均为受控条件，不证明开放调查、真实抽取与调查联合收益、模型摘要优势或生产采用价值。


## 实采结果

采集按上述冻结设计完成：adaptive 32 次、full 16 次，全部 HTTP 200，无重试、uncertain、unknown、refusal 或 error。两条件各 16 个 planned episodes 全部完成；授权封套在完成后关闭。以下为本项目实测，非模型文档主张。

| 条件 | 终局损失 | 材料读取成本 | 总损失 | family 等权均值 | 错误承诺／暂缓 | 原生请求 |
| --- | ---: | ---: | ---: | ---: | --- | ---: |
| 立即停止（synthetic） | 36 | 0 | 36 | 2.25 | 0／12 | 0 |
| 全部读取＋Luna | 12 | 32 | 44 | 2.75 | 0／4 | 16 |
| 按需核查＋Luna | 12 | 16 | 28 | 1.75 | 0／4 | 32 |
| 最优策略（synthetic） | 12 | 8 | 20 | 1.25 | 0／4 | 0 |

每类两个世界、各两次重复，条件内的行均值、按先验均值与 family 等权均值在这份默认设计中恰好相同。固定检查表总损失 44，一步 VOI 与多步 oracle 均为 20；确定性控制不能记成实际模型成绩。

按需核查的行为在两次重复中一致：

- `current-policy` 和 `version-binding` 的 8 episodes 均先问 `current`，随后选对行动；每例总损失 1。
- `already-sufficient` 的 4 episodes 直接 `commit:activate`，没有无效读取；每例总损失 0。
- `unavailable` 的 4 episodes 依次问 `current`、`archive`，最后 `abstain`；每例总损失 5。两种观察在该 family 都不能区分世界，精确策略会立即暂缓、损失 3，因此多出的 8 个成本单位全部来自无效核查。

完整原文没有降低本轮的终局错误：两条件均无错误承诺、均正确保留四次业务暂缓；按需相对 full 的总损失下降 16，来自少读材料。**按需并未节省模型 API 资源**：其输入 tokens 为 31,448、串行请求耗时合计 46.892 秒；full 为 18,724 tokens、21.313 秒。耗时是单次请求延迟之和，不是独立用户体验实验；本地材料读取成本与 API 资源不得合为一个未经定义的总分。

当前复算从保留 bytes 重新解码，逐请求核对 48 次 accounting。API 的 usage 含嵌套缓存明细，冻结版本的汇总显示未知；源码随后补齐递归汇总，原始报告保留，当前重分析补出上述 token 总数。终局动作、轨迹、来源展示和全部损失与冻结结果相同。没有改写原响应、按新规则重采或追加模型请求。

此结果支持有限已知模型中的“找到有用来源”与“及时停止”应分别评价。它不证明开放检索能力、真实抽取与取证联合收益、等 token 优越性或一般模型排名；4 个作者设计机制与重复不足以提供总体泛化区间。
