# 官方 Luna：材料 × 待核实提示

**状态：已完成真实采集与本机审计。** 以下事前设计在首次真实调用前与原创题本、完整首轮原生请求、源码及 operator 一起冻结；结果在文末追加，没有按结果改题或重跑。

## 问题与操作

上一轮[反证调查](../counterevidence/continuation-2026-11-07.md)观察到充分材料下仍核查，但其输入同时提醒初步材料可能有误。本轮检验待核实警告包与实际材料充分性对首次行动的影响。使用八组新题，不把新题和封闭查询契约下的结果直接当成上一轮行为的因果解释。

八组题每组两个相反真值的世界，每世界两次重复，四条件每格 32 episodes，共 128。材料条件为完整记录／缺关键事实；提示条件为警告包／无警告包。警告包仅增加 `initial_dossier.provisional: true` 和 `notice`；没有警告不等于宣称材料经过核验。其余字段必须逐项相同。

公开任务明确：规则及完整记录决定唯一答案，查询只返回本题同一份原始记录，没有其他更新或隐含条件。首次四种业务动作是允许、不允许、暂缓、查询；选查询后才补一次终局请求。查询得到实际该世界的完整记录，不能用 oracle 答案或未查材料替代。

## 事前终点与判读

主要终点为首次查询。记 Q 为各格完整 planned 分母上的查询率：

- 充分材料下的警告差：`Q(sufficient_warning) − Q(sufficient_neutral)`。
- 缺事实下的警告差：`Q(missing_warning) − Q(missing_neutral)`。
- 各提示下的材料差：`Q(missing) − Q(sufficient)`。
- 交互：缺事实下警告差减去充分材料下警告差。

只有相关配对的首次动作完整可观察时才计算这些率与差值。否则报告已观察查询数、完整 planned 数和不可观察状态，相应行为率／差值保持 `null`；不能将 API failure 或 missing 隐式记成没有查询。

同时报告首次暂缓、无充分依据直接决定、终局正确／错误／暂缓／API failure／missing、读取成本及真实调用用量。效用保持查询 1、错误决定 10、暂缓 3、API failure 12；不把效用分数当真实成本。

如果充分材料下警告提高查询、缺事实下变化小，将支持警告包诱发额外查询的有限解释；如果无警告仍普遍查询，单独去除该警告不足以消除行为；如果两种提示都能区分完整与缺失材料，说明在该封闭契约下观察到相应区分。零差异也必须完整报告，不能事后换措辞、选题或重跑追分。原生动作不揭示心理原因。

报告每题的配对结果。八组手工题、两个世界和两次重复不构成 128 份独立资料；不作显著性检验、总体泛化或模型排名。仅测官方 Luna，不声称优于普通 LLM。警告两字段的效应不拆成单词或布尔字段的效应。请求先后随机化能减少时间混杂，但服务 alias 仍非固定权重快照。

## 采集与停止

固定官方 `POST /v1/decisions`、`gpt-6-luna`。首轮 128 requests 按固定 seed 的跨条件顺序串行发送；后续请求依赖真实首轮选择，再随机化串行发送。首请求就是正式样本，无额外预检样本。

上限 **256 attempts、2 MB 序列化输入、US$1 本机保守费用预留**；不续用已关闭实验的授权记录。仅复用本任务已授权的现有凭据与 credits；不新 key、充值、切换模型或自动重试。HTTP／原生契约／usage 异常及网络异常触发停止。失败原样保留，未发送与 uncertain 不重发、不补成业务选择。

2026-11-07 核对：官方 Decisions 未缓存输入 0.10 USD／百万 tokens、输出不收费；缓存写入、区域和长 context 规则另计。每请求先做保守预留，再按已报告 usage 回填；估计不等于账单或余额。[官方 Decisions 规则](https://developers.openai.com/api/docs/guides/decisions)。

默认 CLI、测试及 synthetic 控制均无网络。模型仅接收原创合成可见输入；整份设计、manifest、隐藏真值、研究包和账户数据不发送。raw bytes、冻结源码、operator、计量和身份绑定保留本机；公开页面只发布方法和汇总。

## 实际结果

2026-11-07 完成 **128 个 planned episodes、144 次原生请求**：首轮 128 次，实际选择查询的 16 个 episode 各补一次终局。全部 HTTP 200、原生动作有效；业务终局 128/128。API unknown／refusal／error、missing、uncertain 与本机重试均为 0，没有 fallback。采集封套已经关闭。

每格分母均为 32。直接决定包含正确与错误决定；暂缓是正常业务动作。

### 能说明什么

在这套封闭查询契约和八组题中，警告包改变了部分缺信息题的首次行动，没有诱发充分材料下的重复查询。去掉警告也没有让模型更善于主动补齐材料：缺失无警告组查询为 0，20 次无充分依据直接决定中有 10 次错误。不过该组另有 12 次暂缓，而充分无警告组为 0，因此不能据查询率相同就说模型完全没有区分材料是否齐全。

更多查询也不保证决定正确。签发人资格题的缺失有警告组四次都查询，却仍有两次错误终局；双重条件题从四次暂缓变为直接决定后出现两次错误。充分有警告组的错误从 8 次降至 2 次，虽然两组均未查询；这是预先保留的次要终局观察，不能据此断定其内部注意、信念或推理机制。

本轮结果不支持把警告包概括成“一律诱发过度查询”，也不支持把它当通用修复。新题、明确的同记录查询契约、动作与效用提示和旧反证题不同；不能把新旧差异单独归因某一句提示。只有一个服务 alias、八组手工合成题及两次相关重复，没有总体显著性、跨领域外推、普通 LLM 对照或生产采用证据。

### 证据与复现边界

首轮 body 逐项核对了两字段隔离、缺失双世界输入相同和完整记录真值。正式采集后逐项复核原始 bytes／解析结果／状态／用量／request identity，按实际上一轮回答重建两轮 manifest，并复算完整报告和配对对比；每条原生请求只计一次。原始轨迹、冻结源码、operator 与账户计量仍只保留本机，页面不提供账户读数或原始响应。

离线 oracle 控制为 64 次查询、128 个正确终局、总损失 64；always-query 为 128 次查询、128 个正确终局、总损失 128；stop 为 64 个正确终局、64 次暂缓、总损失 192。这些规则控制知道有限题本与条件，用于验证构造和评分，不能视为同信息模型对照。

统一离线入口通过 473 个 Python tests、现有前端行为检查及 40 页构建／链接检查；独立源码复核和两轮原生 fixture accounting 通过。CLI 与专用报告已具备复现路径，没有新增 Studio 研究类型或公开部署。
