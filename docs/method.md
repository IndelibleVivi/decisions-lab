# 怎样读一个决策实验

把一个判断问题压缩成有限选项，会让结果更容易接入代码，也会让任务设计本身成为决定性因素。实验必须先说清楚“这个判断为了什么”。

## 四种证据，四种结论

| 证据 | 能说明什么 | 不能直接推出什么 |
| --- | --- | --- |
| 官方文档 | provider 当前公开承诺的 contract | 某个账号实际可用、实现没有偏差 |
| 作者报告 | 作者在其设置下报告的结果 | 我们复现了训练或推理 |
| 历史输入复算 | 给定记录的计算能否重现 | 当前模型的质量、因果机制 |
| 本地真实运行 | 确切输入/版本/路线的行为 | 未测试任务、语言或部署条件的效果 |

本仓库把离线合成 demo 单独标识，不将其填入第四行。历史研究的结论必须带着日期、任务和限制一起读。

## 先写任务，再挑模型

next-action 的目标是帮助人决定下一步去哪里核对。它不判断资料“绝对重要”，不替人决定长期项目方向。一个输入可以有多个合理动作，所以标签允许集合；评估看选择是否落在可接受集合内。

先与简单规则比较。如果输入缺失，规则就能要求补全；没有必要用模型重新猜一次。模型可能增益的部分是条件、否定、适用范围以及任务和文本之间的关系。这是需要实测的假设，不是当前质量结论。

## 分数应当能让错误显形

至少同时观察以下内容：

- 正常作答中的正确率，以及在全部案例中的正确数；只报告前者会藏掉拒答和失败。
- unknown、refusal、HTTP/transport/parse error 的数量。unknown 是显式选项，`needs_more_context` 则是合法的下一步动作。
- 每个 source group 和语言的结果；同一材料翻译后的多个案例并非独立样本。
- 选择性覆盖率与保留案例的错误率。阈值只能在 dev 上形成，再对 held-out test 报告；不要在 test 上调到好看。
- 真实返回的 usage、观测延迟和原始概率。未提供 cost 就写 null；价格表估算不叫账单。

本轮 CLI 可以重放、拒绝缺失/重复/错配记录，并按显式 maxP 阈值查看覆盖；25 个合成案例适合检查流程，不足以支持可靠的校准曲线、统计显著性或部署收益声明。

next-action 的两条 adapter 选项说明目前固定为英文，案例正文与问题包含中英文及混写。因此语言切片反映的是这组实际混合输入条件，不能称为完整的中文能力评测；纯语言对照还需要成对翻译同一 rubric 并保持其余条件不变。

## 结果状态与输出类型

首页信号场展示 Choice 任务的**手动试选或离线示例**。其中 `outcome` 是本项目归一化记录的状态，不是所有 provider 都直接返回的同名字段。

| outcome | 这里的含义 | 与已有选项的关系 |
| --- | --- | --- |
| `ok` | 选中任务明确提供的业务选项 | 包括补上下文、交人工，以及文案写着「拒绝」或「都不适用」的业务答案 |
| `unknown` | 显式选择请求中提供的 `unknown` sentinel，保留判断 | 不算可采用动作；界面独立展示，但请求仍保留这个选项 |
| `refusal` | API 的原生拒答 | 没有选中任何选项；不是 NPC 的「直接拒绝」台词选项 |
| `error` | 网络、HTTP、解析或响应契约失败 | 没有有效选项；缺失 choice 也不能自动补成 unknown |

`unknown` 的具体任务含义由选项契约决定。next-action 中它表示没有所提供的动作适配输入；`needs_more_context` 则是应先补材料的有效动作。其他配方若另有「都不适用」等业务选项，也不能只凭相似文案把它们自动归成 unknown。TypeSafe Jev 与 OpenAI Decisions 的原生拒答支持不同，具体归一化规则见[实验 contract](../experiments/next-action/README.md)。

选中已有选项会更新路线和 `ok`；unknown 有独立的 × 出口与读数。点击「看 API 拒答示例」或「看调用失败示例」会清除当前选项，显示明确标注的离线状态；再点一个选项即可离开示例，也可清除回到未试选。复制的通用任务 JSON 始终来自 catalog，不包含试选或示例结果。

新增的 [API 能力实验](../experiments/api-capabilities/README.md)使用独立的多问题离线记录，可分别检查 Choice、Predicate／Noul、Score；它不改变首页试选的含义。公共[研究账本与比较](research-infrastructure.md)保留 planned/missing 和失败分母，按 source family 聚类；少簇仅作描述。数值答案、原生选项质量和 confidence 不能互换，单问／打包与粗／细菜单也必须区分，见[能力方法](api-capabilities.md)。

状态也不同于输出 primitive。带日期的 [10-15 API 核查](../research/2026-10-15/README.md)讨论 Choice、Score、Box 等类型；首页及 next-action adapter 只演示固定 Choice profile，没有实现其它 primitive 的交互或真实调用。概率分布和 provider confidence 是另一些返回字段：手动选择不能推导出它们，所以结果区保持「未调用模型 · 无测量值」。下面的概率地形另标数学示意，历史矩阵另标历史复算，两者都不作为此次试选的模型结果。

## confidence 的名字不是共同标尺

概率分布描述给定选项下的预测。provider confidence 可能由分布另行计算。两者都不是经验证的“答对概率”。选项数、选项描述和被遗漏的合理选项都会影响含义；一个封闭集合可以很自信地选错。

历史复算里，Jev 在 model-router 子任务有 184/375 个 maxP ≥ 0.9 的案例选错，而在 tool-selection 的同一阈值下为 0/391。任务差别已经足以推翻“统一 0.9 就放心”的做法。数值、原始设置与限制见[首期研究](../research/2026-10-08/report.md)。

### 一个数字不能替代它的单位和定义

取一个纯数学示例：有序 level `0/1/2` 的概率为 `[0.1, 0.3, 0.6]`。最可能 level 是 `2`，期望下标是 `0×0.1 + 1×0.3 + 2×0.6 = 1.5`。`1.5` 的单位仍是下标；除非任务另有映射，它不代表 1.5 天，也不代表 75% 的正确率。

新的字段取值又有另一套对象：标量值、来源位置、缺失概率、预测区间。Clairic 官方示例允许 `value=null` 与高 confidence 同时存在，现有 Choice maxP 阈值不能直接移植。类型、来源和下游用途如何分别检查，见[类型化输出](typed-values.md)及[10-20 核查](../research/2026-10-20/README.md)。

| 观察 | 应记录的区别 |
| --- | --- |
| 合法 scalar `null` | 模型给出的缺失判断；继续检验它是否漏掉了真实存在的信息 |
| 返回中根本缺少字段或类型不符 | 响应契约问题；不能悄悄补成 null |
| 空列表 | 该列表没有返回项目；逐项检验漏提和误提 |
| HTTP／解析错误 | 本次没有有效输出；计入完整任务分母 |
| Choice `unknown` | 当前任务定义中的退出项；不自动等于字段缺失 |

在专门研究“何时应保留判断”的新实验中，正确退出可以是成功行为，但仍没有可采用动作。因此分别报告**判断正确率**和**行动覆盖率**。现有 next-action 的 `acceptable` 和 replay 口径不因此改变。

## 下一次实验怎样增加信息

先冻结任务定义和 dev/test 分组；记录实际 model、endpoint、时间、请求、响应与失败。再比较确定性 baseline 和候选路线。增加一次干预时保留其余条件，例如只改变选项顺序，或只切换等义语言版本，并先测完全重复请求自身的变化。

首期还保留了 [12 项 contract probe 方案](../research/2026-10-08/public_probe_protocol.json)，状态仍是 NOT_RUN：选项顺序、问题 ID、独立问题批量、语言、unknown、上下文位置、概率输出、score 均值/众数、refusal/invalid 与图像约束。next-action 是用途实验；这些 probes 是接口与行为检查，二者不能互相冒充覆盖。
