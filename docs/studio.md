# 本地研究台

研究台是 Decisions Lab 现有首页的「实验 D」区域。首页的粒子、玩法、概率地形、历史矩阵和练习使用同一构建；本地 API 为其中的研究区域提供持久化与复算。

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements-site.txt
.venv/bin/python -m decision_lab studio --port 8776
```

当前支持 macOS／Linux、Python 3.11+。打开终端显示的本地地址。默认 workspace 为 `runs/studio`，可通过 `--workspace` 指向仓库外的本机目录。静态阅读站只显示启动说明，不连接本地 API、不上传研究。服务仅绑定 `127.0.0.1`；停止服务不会删除研究。

选一份 E1、E2 或 E3 题本，编辑问题、竞争解释、条件与重复，保存并冻结。冻结后可运行明确标注的离线控制，或下载当前原生请求，通过既有 CLI 采集后导入记录。模型采集仍需独立模型、输入与全程预算授权；研究台不发送 provider 请求。

研究的设计、运行证据、分析与笔记各自保留。修改冻结设计时派生新研究；重新分析不会覆盖旧结果。导出的 JSON 研究包包含输入和回答，可能含私人资料，分享前需检查。包不包含可执行解释器；历史复现需要本机原有解释器和匹配的 Python runtime，缺少时明确报告不可复现。


## 一次研究怎样走完

1. 在实验 D 装入 E1、E2 或 E3，写下研究问题和竞争解释。同一会话支持 2–8 个条件，包含原生路线、模型、离线 policy、重复；E3 另有表示路径与 gold-stage 干预，可容纳三路径及完整阶段对照。完整 JSON 编辑器用于调整题本、候选、rubric 或有限世界。
2. 保存草稿。每次保存校验原生可表达性，revision 冲突会拒绝覆盖；未保存离开会提示。冻结固定设计与全部 planned slots，并建立初始 missing 分析。此后改变设计应派生新研究。
3. 运行离线对照，或下载当前请求后导入既有记录。E1 支持 api-record、api-responses 与 api-lab collection；部分响应保留缺失。E2/E3 支持完整 workflow 或当前回合／阶段的原生记录，严格绑定冻结输入；不完整或 uncertain 回合保持待处理，不会跳过阶段。每次导入或运行追加证据和分析。
4. 点证据矩阵中的样本，查看保留请求、原生回答、测量定义与完整记录。E1 同时保留 classification error 和 numeric absolute error，按测量分开阅读；E2 保留查询成本、先验加权和等 world 口径；E3 保留字段、来源与终局决定的区别。
5. 在比较页选择分析版本。复现用该分析保留的解释器和同批 evidence；当前重分析仍绑定那批 evidence，另存差异。研究笔记和反例绑定所选分析，之后重算不会改写原结论。
6. 再次启动相同 workspace 即可重开。导出保留设计、各批原生证据、分析和笔记；导入建立新的本地会话，旧报告标为导入声明，并追加当前本机的复算。

## 配对与版本的边界

E1 冻结时生成显式 scientific pairing。两侧的科学输入、候选、gold、测量和 planned 身份必须相同；路线、模型和原生 manifest 继续保留。它不是允许任意不同任务按相似名字强行对齐。数值题的 absolute error 不替代原生答案或原来的正确性标记；异质测量分别比较，不能加成总分。confidence 标签不证明与其他 primitive 或 route 的信号同义。

E3 比较分别显示正确决定、与确定性 body policy 的一致数及 gold 干预。policy agreement 不代表诚实度或语义充分性；`synthetic` 来源标记也不代替阶段干预说明，原生 decision 可以读取本地 gold 值。具体限制随日期研究保留。

解释器快照由本机 `decision_lab` 源码及 Python 版本确定，复现前逐文件验证。JSON 导出不包含这些可执行文件，不会从导入包安装解释器。另一台机器只有具备相同本地解释器与 runtime 才能复现旧分析；否则可查看导入报告或用当前版本重分析，不能把这称为历史复现。digest 用于一致性检查，不认证 provider 调用或报告作者。

## 本机存储与失败恢复

研究 JSON 和解释器位于 workspace 的 `studies/` 与 `interpreters/`，保存使用原子替换；不要手工改写冻结数据或保留源码。仓库内 workspace 只能位于忽略的 `runs/`。备份整个 workspace 才能同时保留数据与历史复现能力；导出 JSON 适合可检查的数据迁移。

服务只允许本机 Host/Origin，写入需要当前页面的 session token。服务重启后旧标签页须刷新；两个标签页同时修改时，旧 revision 会被拒绝，重开研究后再编辑。端口被占用时改用 `--port`；不应停止无关服务。保存失败、导入不匹配或复现失败时，已保存的研究不变。停止服务后，已存在的原始 CLI 记录和研究会话仍留在本机。

本地使用会保留输入、回答、模型/路线和分析笔记；公开阅读站的构建 allowlist 不包含这些内容。历史 provider 报告与当前 synthetic 控制各有自己的证据来源，Studio 不认证 live 运行、不恢复旧采集授权、不执行模型建议。
