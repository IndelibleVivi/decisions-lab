# Decisions Lab 的研究主线

本项目研究一个持续的问题：**把模型输出约束成可检查的判断或取值以后，它究竟保留了什么意义，能否改善后续决定？** 接口合法、字段正确、证据充分、组合正确和任务有用，是需要分别建立的证据。

这也包含建设性的探索：一次 Choice 能否成为可执行的小程序，多种类型能否组成计算链，图片能否重新定义判断规则，有限问题能否构成有成本意识的调查。实验既要发现原语能做成什么，也要找出成立条件与竞争解释。

项目的成熟形态是一座可以不断提出、反驳和修正假设的实验工作台。读者从一个能力主张进入，能找到有日期的来源、明确的研究问题、可复现任务、原生请求、失败与反例，再判断下一次实验能增加什么知识。阅读站让这些关系可理解，CLI 让它们可运行；两者共享事实来源。

## 这一阶段为什么转向连续取证

静态题本能测“给定这些材料，答案是什么”。工作流还需要回答“材料不够时问什么、问完是否改变判断、何时应该停止”。只有单步正确率，很难分辨一个模型是否靠更多查询增加成本，是否过早承诺，或是否在得到关键材料后仍然失败。

主动取证将 query → reveal → 下一轮输入 → commit / abstain 变成可重放过程。查询仅揭示本地合成环境中的指定观察；模型输出不执行外部动作。每轮继续使用既有 api-lab 原生请求和 collector，保留 transport 与语义的边界。

一步 VOI 比较“问一个问题以后立即决策”的预期收益与成本。它可能错过信息互补：两个均匀比特的 XOR，单独知道一个比特不能降低错误风险，两个一起才足够。有限预算动态规划另行求出完整多步最优策略；它是有精确先验和观察模型的研究 oracle，不是对模型能力的代言。

方法参考 [Dong 等的 VOI 框架](https://arxiv.org/html/2601.06407v1)中成本敏感的 clarify-or-commit；其中实际方法使用一步 lookahead。区分 myopic 与 nonmyopic 分析的理论依据见 [Heckerman、Horvitz 与 Middleton](https://www.erichorvitz.com/nonmyopevi.htm)。本项目使用原创有限世界和精确枚举控制，不复制这些工作的实证结论。

## 连续建设的顺序

1. **先建立可判错的连续实验。** 本阶段贯通主动取证、预算与状态、原生逐轮回答、失败保留、终局损失和对照。检查表、立即停止、一步 VOI 和多步 oracle 都看相同的可见契约。先用确定性控制检验测量，真实模型实验另行冻结模型、输入、重复和预算。
2. **再定位证据在链中怎样丢失。** 将 typed extraction → 确定性计算 → decision 接到同一任务，加入 gold 抽取、gold 检索、gold 计算和等预算摘要对照。区分字段错、schema 本身不充分、算错与下游判断错；不把每次失败都归因于模型抽取。
3. **再扩大外部效度。** 使用新机制族、公开真实资料与版本变化，研究语义寻址、旧证据和时间乱序怎样改变最终损失。已见题仅作开发证据；表示变体与重复不能冒充新的独立来源。
4. **最后研究采用。** 在完整轨迹可回看后，再做固定 AI 输出下的人类纠正、错误跟随和验证成本；私人工作流旁路与生产执行各有自己的输入、权限和接受条件。

这些层次保持同一个终点：说明模型在哪一环提供了什么、比简单规则多带来什么，以及在哪些条件下应该不用它。负结果、暂缓和“确定性代码已经足够”都是有价值的研究结论。

## 10-28 的阶段推进

E2 首次模型实验完成 184 次原生请求、96/96 episodes。Clef/Mammoth 在这份已知有限模型上达到 oracle 同损失；Flash 完成 XOR 两问，却在不可得和无信息条件上多付成本或过度暂缓。这说明下一步不能只扩充“会不会问”的静态题数，需要定位证据如何进入并约束后续决定。

E3 将实际导入的上一阶段响应接入下游 body，以三路径和 gold-stage 干预分开字段错误、schema 盲点、计算和最终判断。源码与离线控制的贯通先于 provider 研究；等 token 普通摘要对照、公开真实材料、时间/来源混乱和跨机制新题仍是后续效度门槛，不能从当前有限控制推断完成。

## 如何决定下一次开发是否值得

- 新模块应连接一个仍未回答的研究问题、一个可拒绝错误解释的对照，以及一个能回到原始证据的结果。
- 先检查现有生成器、原生记录、collector 和 comparison 能否承担责任。新增 transport、通用 router 或常驻服务，需要具体任务带来的理由。
- 报告动作推荐覆盖、最终决定覆盖、业务暂缓、API unknown/refusal/error 和 planned missing；保留查询成本与终局损失的单位。
- 条件性路径 regret、完整策略的 expected regret、单次实际损失和 provider 账单是不同对象。没有相应证据就保持未知。
- 不用新命令数量、测试数量或更多静态案例代替能力贯通；也不为了显得通用而抹平原生类型与证据边界。
