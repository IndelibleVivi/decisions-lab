# 从选答案，到提取可以核对的值

[三组完整实验](../experiments/typed-values/README.md) · [10-20 契约核查](../research/2026-10-20/README.md) · [原有 Choice 方法](method.md)

一份交付说明写着：“当前订单尚未确定交付日期。上一张订单已在 10 月 18 日交付。”如果任务只问“接下来做什么”，有限选项模型可以建议补材料。但如果应用要填写当前订单的交付日期，就必须决定哪些文字属于当前订单、日期是否存在，以及空缺怎样保留下来。

这增加了一类值得实验的问题：**一个能被程序读取的值，怎样才能保留它来自哪里、如何得到、仍缺什么。** Cloudflare 的 Clairic 提供了一个具体入口；本页的方法并不依赖某一家服务。Clairic 的版本、原生字段和限制以 [10-20 核查](../research/2026-10-20/README.md)为准，下面的案例与流程是本项目的原创实验设计。

## 先问：这个输出究竟是什么

同一个字段名 `result` 可以装完全不同的东西。任务设计应先确定结果的含义，再挑输出类型。

| 要完成的事 | 本项目的例子 | 合适的结果 | 怎样核对 |
| --- | --- | --- | --- |
| 在已知动作中选择 | 继续处理、先核争议、补材料 | 一个动作 ID，可另带选项分布 | 对照动作定义和可接受答案 |
| 从材料中摘录 | 当前订单的收件人 | 原文文本与位置 | 文字存在，且确实属于目标订单 |
| 归一化或计算 | 单价 × 数量 + 运费 | 有单位的数字、日期 | 核对操作数、单位与运算规则 |
| 估计尚未知晓的结果 | 这张工单多少天后完成 | 点估计及预测区间 | 等结果出现后统计误差与覆盖 |
| 写出新的内容 | 给客户解释为什么需要补材料 | 开放文本 | 核对事实、表达和用途 |

“结构化输出”描述的是返回契约。JSON 能解析、字段类型正确，只解决了其中一部分；表格里每种任务需要的正确性证据仍然不同。Cloudflare 的[概念文档](https://developers.cloudflare.com/workers-ai/concepts/extraction-models/)也分别讨论摘录、计算与预测，本页把这一区分落实到可检查的实验条件。

## 一个合法的 span 仍然可以指错人

设原文包含两张订单：

```text
当前订单 PO-842：收件人为林遥；没有列出交付日期。
归档订单 PO-497：收件人为周岚；交付日期为 2026-10-18。
```

返回 `周岚` 时，字符串确实存在，位置也可能完全正确。错误发生在归属：我们问的是 PO-842。返回 `2026-10-18` 同样能通过日期格式检查，却把上一张订单的事实挪到了当前订单。

因此，一条提取结果至少有三层可分开的判断：

1. **结构成立。** 类型、字段和数值格式是否符合契约。
2. **定位成立。** 返回的文字能否在本次实际输入中找到。
3. **关系成立。** 这段文字是否回答了指定实体、版本和时间范围下的问题。

我们为[实验一](../experiments/typed-values/README.md#实验一-缺失值与来源归属)设置的错误样本，恰好让前两层成立、第三层失败。这能检查系统是否把“有出处”误当成“引用正确”。

位置还要与精确输入绑定。页面更新、换行变化、Unicode 归一化或截断都会影响位置。Clairic 官方页说明 text 返回原文位置，但本轮没有建立这些位置按 UTF-8 字节、Unicode code point 还是 UTF-16 code unit 计数，也没有验证端点的开闭约定；不能直接把它代入某种语言的切片。实验先保留完整 `state`，使用含中文、emoji 和组合字符的探针确认约定，再启用位置自动验收。[字段来源与待验证项](../research/2026-10-20/README.md)

## 空值本身也携带信息

下面几种“没有结果”不能互换：

| 观察到的情况 | 这一层可以说什么 | 应保留什么 |
| --- | --- | --- |
| Choice 显式选了 `unknown` | 未采用任何已有业务动作 | 原始选项与选择结果 |
| 单值提取返回 `value: null` | 模型没有给出可采用的字段值 | 原始字段结果和材料是否真的含值的编辑标签 |
| 列表为空 | 本次没有返回匹配条目 | 空列表，不能擅自补成单值 null |
| 接口原生拒答（如该 API 定义）或请求失败 | 没有正常完成这个判断 | 原生拒答或错误状态，不能补成“材料中没有” |
| estimate 返回一个值 | 产生了一次预测 | 预测条件与区间，不能据此认定材料足够 |

这张表比较不同 API 与输出类型，右列是本项目的记录建议，不是 Clairic 的原生状态枚举。Clairic 的字段语义来自 [Clairic 模型页](https://developers.cloudflare.com/workers-ai/models/clairic/)与[提取概念文档](https://developers.cloudflare.com/workers-ai/concepts/extraction-models/)；本轮核查的 schema 没有独立的 `refusal` 或 `unknown` 状态。仅在 API 明确定义原生拒答时保留它，不能从 null 推断拒答。

Clairic 的官方购买订单示例值得特别看：字段的 `value` 是 null，同时仍有一个非空 `guess`、对应 span 和很高的 confidence。**不能写成 `value ?? guess`，把缺失值偷偷填回来。** 那会抹掉服务实际返回的空值语义。我们也不根据 confidence 的名字，自行发明它的计算公式。[官方示例及核查](../research/2026-10-20/README.md)

评估空值时需要两类标签：本来存在的值有没有漏掉，本来不存在的值有没有被填上。只报告“成功提取多少字段”会把第二类错误藏起来。实验资料里的 `editorial_oracle` 提供这种人工真值；它不是模型响应，也不应进入请求。

## 抽出字段以后，哪些事情让代码做

考虑一份原创采购材料：三件货物，单价 350.00 CNY，运费 50.00 CNY。按明确公式，金额是 1100.00 CNY。让代码计算这一步，可以消除一类算术错误，也方便单独核对操作数。

但“金额没有超限”还不足以决定是否建议继续。如果同一材料另有一句“第三件尚未验收，争议未解决”，仅保留数量、单价、运费的投影已经丢掉了决定性信息。

我们在[实验二](../experiments/typed-values/README.md#实验二-算对金额以后该做什么)比较三条路径：

| 路径 | 下游决策能读到什么 | 它能暴露的错误 |
| --- | --- | --- |
| 直接判断 | 完整原文与相同任务规则 | 是否找得到关键条件 |
| 只给字段 | 提取的金额要素与代码计算结果 | 数值正确，但语义条件丢失 |
| 字段带来源 | 相同数值、目标实体/版本与验收争议原文 | 来源保留是否足以恢复判断 |

三条路径必须使用同一套动作定义和评价标签；先重复相同请求，再一次改变一项条件。实验所测的是这些具体信息投影的后果，不预设哪条架构普遍最好。若简单的明确规则已经完成任务，也应保留这个有用的 baseline。

数据血缘可以保持很小：源材料 ID、精确文本、目标实体/版本、提取字段、用于计算的操作数、确定性计算结果、采用了哪些原文段落。一次算对只能支持“这次运算正确”，不能替尚未核实的争议状态背书。

## 分数的单位，和数字本身同样重要

这里有一个完全离线的算例：有序 level `0/1/2` 的分布是 `[0.1, 0.3, 0.6]`。众数下标是 `2`，期望下标是 `1.5`。两者都能正确地描述这份人为设置的分布，却不是同一个统计量。

`1.5` 也不会自动变成“1.5 天”；只有任务明确给出了 level 与业务量的对应关系，才有这种解释。provider confidence、选项最大概率、字段正确率、数值预测区间也各有自己的含义。现有 [Choice 方法](method.md)里的 maxP 覆盖分析，不能直接拿来筛选日期或估计区间。

## 预测区间需要等现实给答案

如果模型返回 `p10` 与 `p90`，这两个分位点界定的是预测分布中间的一段。它在新任务上实际覆盖了多少结果，要在结果揭晓后另算；把日期范围限制在下周，也不能让现实中的任务一定下周结束。[Cloudflare 的不确定性与约束说明](https://developers.cloudflare.com/workers-ai/concepts/extraction-models/)

实验记录需要保留预测时点、当时可见的材料、预测区间，以及后来独立记录的结果。对成熟样本同时看区间覆盖率和宽度：非常宽的区间可能容易覆盖，窄区间则可能漏掉大量真实结果。尚未完成的任务应报告为待观察；不能把它们当作零天，也不能无声删掉这些可能特别慢的案例。

[实验三](../experiments/typed-values/README.md#实验三-区间是否兑现)给出一份完整原创工单输入、确定性基线及时间切分方法。里面没有模型预测数值；模型结果栏仍为空，已有数字属于输入材料、编辑真值或基线计算。

## 本轮能拿到什么

[实验册](../experiments/typed-values/README.md)和 [JSON 资料](../experiments/typed-values/examples.json)提供三组原生请求草案、原创输入、编辑答案、控制变量与评分规则，状态为 **NOT_RUN**。它们可供人工核对及后续实现；当前 `decision_lab` CLI 仍只接受原有 next-action 契约，没有新增 Clairic collector。

原有配方继续适合有限选择任务。新资料帮助下一次扩展先确定：要保留的是一个动作、一段证据、一个算出来的值，还是一次等待验证的预测。
